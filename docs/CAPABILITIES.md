This map covers the guide, both agent definitions, and the dormant Benny pack. The refresh adds help but does not add a cloud, model-routing or automation runtime. See [delta disposition](VALIDATION.md#delta-disposition). The port distinguishes a procedure from an installed or verified runtime capability.

`Ported` means a host-independent workflow remains available as instructions. `Adapted` means a Codex route or explicit fallback replaces an upstream assumption. `Unavailable` means this port does not provide that service. Neither ported nor adapted means every application integration has been exercised.

## Evidence and limits

Local `codex --version` reported `codex-cli 0.160.0`. Read-only `codex --help` advertised `exec`, `review`, `agents`, `plugin`, `app-server`, `resume`, `fork`, model and worktree options. `codex features list` reported `multi_agent`, `multi_agent_v2`, `in_app_local_automation`, browser/computer-use, plugins and worktrees enabled. Feature flags describe this installation; they do not prove service availability, custom agent registration, supported external events, permissions, or credentials. No CLI inference or live external write was run for this audit.

The official [Codex skills documentation](https://learn.chatgpt.com/docs/build-skills) documents project `.agents/skills`, user `~/.agents/skills`, symlink discovery and invocation policy. The official [app-server documentation](https://learn.chatgpt.com/docs/app-server) documents the skills listing interface. These supersede assumptions imported from Cursor; see [CODEX-EVIDENCE.md](./CODEX-EVIDENCE.md) for the local schema/discovery evidence gathered for this port.

The source guides are reference material, not authority. Their examples of autocommit, autopilot merges, external replies and parallel agents remain subject to the user's actual task and Codex's permission model. No public deployment, real Slack/tracker run, scheduled wakeup, cross-provider review or application recording is claimed by this audit.
