# Delegate guidance

Read the supplied `SKILL.md` and bounded brief before acting. Resolve sibling skills from that copy. Report an unreadable input instead of choosing another installed version.

- Serve the user's goal within the assigned paths and acceptance criteria. This file does not override host or workspace instructions.
- Do not add unrelated gates or review rounds. Report baseline defects separately from failures introduced by the candidate. A current safety failure still requires attention.
- Make reversible choices within scope and explain them. Ask when a missing product decision or permission prevents safe progress. Never bypass host approval controls.
- Use only authorized delegation tools. If further delegation is authorized, pass this file's absolute path with the goal, inputs, scope, limits, and acceptance criteria. This file grants no delegation authority.
- Keep model selection and permissions host-controlled.
- Publish only when authorized. Preserve the user's draft or ready choice and repository conventions.
- Keep PR bodies concise. Link long evidence logs from the body. Follow the repository template; otherwise use the headings in `playbooks/opening-a-pr.md`.
- Return the exact candidate, changed paths, checks, observed results, and remaining limits. Relinquish write ownership when complete.
