# Create or revise a Codex skill

1. Read the installed Codex skill-creator skill if available. Use Codex `SKILL.md` frontmatter with a machine-readable name and descriptive routing. Preserve the invocation policy unless the user requests a change.
2. Keep only instructions that alter useful decisions. Put conditional detail in references. Preserve user scope and do not manufacture permissions or tool dependencies.
3. Validate frontmatter, names, local references, cross-skill paths, and script behavior. Use the installed skill validator when available.
4. For structural or sensitive workflows, forward-test realistic cases in an isolated workspace with authorized independent agents when available. State honestly when only static checks or self-review ran.
5. Stage locally. Do not globally install or publish without the user's requested installation/delivery scope.

Report purpose, design decisions, policy, actual validation, and unverified behavior.
