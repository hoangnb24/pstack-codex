# Drive one scoped task to a predicate

1. State the checkable done predicate, task boundaries, available verification, and a practical time/attempt budget. Preserve user limits and explicit approvals. “Keep going” covers the task, not unrelated publication or messages.
2. Work in-session in small units. Observe the relevant event or state through available tools; there is no `/loop` runtime in this port. Do not claim future execution without a separately requested and successfully created supported automation.
3. Each iteration makes one evidence-backed change and verifies it. Keep a decision trail with change, observation, predicate progress, and next action. Revert only your own failed experiment.
4. Fix in-scope blockers. Record unrelated discoveries as follow-ups. Answer steering promptly, incorporate corrections, and obey stop/hold immediately.
5. Stop when done, budget exhausted, blocked by unavailable capability or authorization, or at a genuine dead end. Do not weaken the predicate. Leave a durable resume note for unfinished work.

Report predicate, iterations, accepted/discarded changes, evidence, and remaining state. Never imply an unattended process continues after the turn.
