# Build a throwaway decision instrument

1. Name the decision this prototype resolves. If there is no decision, route to Feature. Separate empirical questions from human preferences.
2. Gather relevant prior art when useful and available. Preserve user design constraints. Do not block a settled direction on a moodboard.
3. Build in an isolated scratch directory using existing tools and the lightest suitable stack. It is a throwaway instrument, not production code. No unsolicited dependency installation or CDN dependency is required.
4. Compare meaningful alternatives behind a labeled switcher for visual work or a repeatable runner for behavioral work.
5. Observe the matching surface. Capture screenshots and interactions for UI; record outputs or timings for behavior. Missing browser/native tooling limits the conclusion.
6. Present evidence, tradeoffs, recommendation, and scratch path. Proceed to production only if the user's task includes it; otherwise stop at the decision.

Report that the artifact is throwaway and what it did and did not prove.
